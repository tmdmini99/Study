
### 1. **User Schema (MongoDB 스키마)**

MongoDB에 저장할 데이터 구조를 정의합니다. 이 스키마는 데이터베이스와의 상호작용을 위한 모델로, 실제 유저 데이터를 어떻게 저장할지에 대한 구조를 결정합니다.


- **목적**: 유저 데이터를 **MongoDB**에 저장할 때 사용합니다.
    
- **사용처**: `UsersService`에서 사용하여 유저를 데이터베이스에 조회하거나 저장할 때 사용됩니다.
    

### 2. **Login DTO (Data Transfer Object)**

DTO는 클라이언트로부터 데이터를 받아서 **서비스 로직**에 전달할 때 사용됩니다. 로그인 DTO는 로그인 요청을 처리하는 데 필요한 정보를 **유효성 검사**와 함께 **전달**하는 역할을 합니다.


- **목적**: 클라이언트에서 로그인 요청을 처리하기 위해 받은 데이터를 **유효성 검사**하고 **서비스 로직**에 전달합니다.
    
- **사용처**: `AuthService`에서 사용하여 클라이언트로부터 받은 로그인 요청을 처리합니다.
    

### **차이점**

- **User Schema**: MongoDB에 저장되는 실제 유저 데이터를 정의합니다.
    
- **Login DTO**: 로그인 요청을 받을 때 클라이언트에서 전달하는 데이터를 정의하고, 유효성 검사 (`class-validator`) 등을 통해 데이터를 처리합니다.
    

### **예시 흐름**

1. 클라이언트가 로그인 요청을 보냅니다 (`username`, `password`).
    
2. `AuthController`에서 `LoginDto`로 요청을 받고, 이 데이터는 **DTO**가 되어 `AuthService`로 전달됩니다.
    
3. `AuthService`는 `UsersService`를 사용해 MongoDB에서 해당 유저를 조회하고, **비밀번호**를 확인합니다.
    
4. 로그인에 성공하면 **JWT** 토큰을 발급하여 클라이언트에게 응답합니다.
