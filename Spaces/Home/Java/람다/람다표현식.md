람다 표현식은 익명 함수를 만드는 문법


기본 문법

```java
(매개변수) -> { 실행문; }
```

- 매개변수는 소괄호 `( )` 안에 작성
    
- 화살표 `->` 뒤에 실행할 코드 작성
    
- 실행문이 하나면 `{}`도 생략 가능

## 기존 방식 vs 람다 방식

### 예제: 버튼 클릭 리스너

#### 🧓 예전 방식 (익명 내부 클래스)

```java
button.addActionListener(new ActionListener() {
    @Override
    public void actionPerformed(ActionEvent e) {
        System.out.println("Button clicked!");
    }
});
```

```java
button.addActionListener(e -> System.out.println("Button clicked!"));
```


### 함수형 인터페이스란?

- **추상 메서드가 딱 하나만 있는 인터페이스**
    
- `@FunctionalInterface` 어노테이션으로 명시 가능 (선택사항)


```java
@FunctionalInterface
interface MyFunction {
    void run();  // 추상 메서드 하나만!
}
```


## 다양한 예제

### 1. Runnable



```java
Runnable r = () -> System.out.println("Running!");
r.run();
```

2. Comparator

```java
List<String> list = Arrays.asList("apple", "banana", "cherry");

Collections.sort(list, (a, b) -> b.compareTo(a));
System.out.println(list);  // [cherry, banana, apple]
```

3. Custom 인터페이스
```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}

Calculator add = (a, b) -> a + b;
System.out.println(add.calculate(3, 5));  // 8

```


## IntUnaryOperator


```java
@FunctionalInterface
public interface IntUnaryOperator {
    int applyAsInt(int operand);
}
```


`int -> int` 형태의 **함수형 인터페이스**에요.  
람다식(익명 함수)을 변수에 넣고 재사용하려고 만든 일종의 타입
```java
IntUnaryOperator op = x -> x * 2;
int result = op.applyAsInt(5); // 결과는 10
```


### applyAsInt
`applyAsInt()`는 `IntUnaryOperator`라는 **함수형 인터페이스** 안에 정의된 **단 하나의 추상 메서드**예요.
### 함수형 인터페이스란?

- 함수형 인터페이스는 **딱 하나의 메서드만 가진 인터페이스**
    
- `람다식`이랑 연결되려고 만들어진 녀석들이에요
    
- 예: `Runnable`, `Supplier`, `Consumer`, `Function`, `IntUnaryOperator` 등
실제 예제
```java
IntUnaryOperator doubleValue = x -> x * 2;

int result = doubleValue.applyAsInt(5); // 10
```

```java
import java.util.function.IntUnaryOperator;

// 람다 정의
IntUnaryOperator calculateIncrement = value -> (value / m) + ((value % m > 0) ? 1 : 0);

// 사용
int need = players[i] - (server * k);
if (need > 0) {
    serverTimeOut.add(i + k);
    server += calculateIncrement.applyAsInt(need);
    answer++;
}
```

### 그럼 왜 이름이 applyAsInt 인가요?

Java에는 다양한 함수형 인터페이스가 있는데:

|인터페이스|입력|출력|메서드명|
|---|---|---|---|
|`Function<T, R>`|T|R|`apply()`|
|`IntUnaryOperator`|int|int|`applyAsInt()`|
|`IntBinaryOperator`|int, int|int|`applyAsInt(int left, int right)`|

➡ `int` 타입 전용이기 때문에 `apply()` 대신 `applyAsInt()`라고 이름이 달라진 거예요.  
자바가 **기본형(primitive)** 처리할 때 박싱/언박싱 안 하려고 만든 차별화된 메서드입니다.


## DoubleUnaryOperator

```java
@FunctionalInterface
public interface DoubleUnaryOperator {
    double applyAsDouble(double operand);
}
```


```java
import java.util.function.DoubleUnaryOperator;

public class Main {
    public static void main(String[] args) {
        DoubleUnaryOperator half = x -> x / 2;

        double result = half.applyAsDouble(8.0);
        System.out.println(result); // 4.0
    }
}
```


### 함수형 인터페이스 비교 정리표

|이름|입력|출력|메서드|
|---|---|---|---|
|`IntUnaryOperator`|`int`|`int`|`applyAsInt(int)`|
|`DoubleUnaryOperator`|`double`|`double`|`applyAsDouble(double)`|
|`Function<Double, Double>`|`Double`(객체)|`Double`|`apply()`|

💡 기본형(`double`, `int`)을 쓰면 성능 면에서 유리하고,  
객체형(`Double`)은 박싱/언박싱 오버헤드가 생길 수 있어요.


```java
import java.util.*;

class Solution {
    public String[] solution(String[] strings, int n) {
        Arrays.sort(strings, (s1, s2) -> {
            if (s1.charAt(n) == s2.charAt(n)) {
                return s1.compareTo(s2); // 사전순 비교
            }
            return Character.compare(s1.charAt(n), s2.charAt(n));
        });
        return strings;
    }
}
```
