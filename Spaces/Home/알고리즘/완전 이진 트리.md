    }

## 참가자 번호는 현실적으로는 **1번부터** 시작하지만,

**컴퓨터 (이진수, 배열, 인덱스)는 0부터 시작**하기 때문이에요.

|참가자 번호 (`a`)|실제 라운드 배열상의 위치 (index)|
|---|---|
|1|0|
|2|1|
|3|2|
|4|3|
|...|...|


## 완전 이진 트리에서 "공통 조상을 만나는 깊이"

### 💡 비유:

토너먼트 구조는 **완전 이진 트리**처럼 생겼어요.

- 리프(맨 아래)는 참가자 번호 (`a-1`, `b-1`)에 해당
    
- 위로 올라갈수록 부모 노드 (= 다음 라운드)
    
- 두 노드가 처음으로 만나는 조상이 = **그들이 대결하는 라운드**

```java
int x = 3;  // binary: 011
int y = 6;  // binary: 110
```


XOR 연산: 어디서 비트가 다른지 확인

```java
011 (x)
110 (y)
---
101 ← XOR 결과
```


## 이진수의 길이 = 공통 조상을 찾기 위해 올라가야 하는 깊이

- `101` = 길이 3
    
- 이건 **위로 3단계 올라가야** 처음으로 같은 번호가 된다는 뜻
    

즉,

- 1라운드 → 번호 2로
    
- 2라운드 → 번호 1로
    
- 3라운드 → 공통 번호에서 만남!


트리 구조 시각화 예시:

```scss

         └─────┬─────┘
라운드 2     [1]     [2]
           ┌──┘     └──┐
라운드 1 [3] [4]   [5] [6]
         ┌┘ ┌┘     ┌┘ ┌┘
참가자: 1  2       3  4

```
